# 新疆以外W0-SCENE遍历实测

日期: 2026-10-07.

## 结果

按指定规则生成643个不同候选ID, 全部实际查询. 151个返回errno=0且basic.svid与请求一致, 492个返回无效, 0个网络或解析错误. 有效记录包含77个非空scenic_id. 150条属于这些景区分组, 另1条ID有效但scenic_id为空.

这些命中包括前几轮已知种子的复核, 并非151条全部是此前未知. 没有对全部151条逐一验证图片或普通坐标扫描状态. 8个代表点均已确认普通xf原坐标r=50为空, 缩略图为可解码512x256 JPEG; 其中3张实际查看.

## 实际生成规则

```text
{region}3{code}W0{YYMMDD}0SCENE{number:03d}
```

例如:

```text
1406 | 3 | C | W0 | 140710 | 0SCENE | 001
1008 | 3 | M | W0 | 141009 | 0SCENE | 001
2308 | 3 | A | W0 | 150228 | 0SCENE | 001
```

不是只猜30-35. 第6个字符code有数字和字母. 本轮初始3批次测试0-9和A-Z全部36个字符. 没有把“像36进制”升级为官方确定的编码语义.

所有候选来自配置文件中的笛卡尔积, 没有将photos/all_scenes/entrances返回的ID加入本轮待查询队列. 接口返回的all_scenes保存在日志中, 仅供复查, 未用于制造遍历命中统计.

## 新规律及异常

1. 日期是很强的批次约束. 先从有效种子取得地区和日期, 再展开代码, 命中率明显优于跨省直接复制日期. 尚不能认定日期一定为真实拍摄日.
2. code不限0-5. 丹东0-9,A-P连续命中, 重庆最远测试命中V, 河南命中A/B.
3. 中间有缺号. 焦作2308代码1命中, 2-7不命中, 8/9/A/B又命中. 第一个空值不能当作扫描终点.
4. 同一W0结构的source并非全部mapshow. 郑州石窟寺230135W01502280SCENE001的source为SOSO, 锦江山异常点为soso.
5. 14063CW01407100SCENE005独立复查仍为type=street, scenic_id和名称为空, 但返回ID匹配, 坐标与公园其他场景相同, 且存在真实可解码缩略图. 应保留ID并单独标异常, 不应直接计入另一个景区或按type剔除.
6. 请求超时或异常与“不存在”分开记录. 本轮最终没有未解决请求错误.

## 复跑

只依赖Python标准库, 配置endpoint/候选地区/日期/代码/序号均外置. 默认3个并发, 全局请求间隔0.3秒, 单次超时8秒. 日志为追加式JSONL, 已查ID自动跳过.

```powershell
python tencent-enumeration.py tencent-enumeration-plan.json --dry-run
python tencent-enumeration.py tencent-enumeration-plan.json --limit 110
python tencent-enumeration.py tencent-enumeration-plan.json --limit 110 --retry-errors
python tencent-enumeration.py tencent-enumeration-plan.json --audit
```

limit限制本次新增请求数量, 不会自动扫描未配置的地区和日期. 修改计划增加候选后再运行, 可续查. 错误重试是显式选项.
